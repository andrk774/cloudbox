# CloudBox

Self-hosted облачное хранилище в духе **Nextcloud**: один бинарник на Go + PostgreSQL. Веб-интерфейс встроен в бинарник, файлы лежат на диске или в S3 (Garage, SeaweedFS, Yandex Object Storage, Selectel), по желанию — в зашифрованном виде.

## Возможности

**Файлы**
- Папки, загрузка файлов и целых папок, drag & drop, перемещение перетаскиванием, копирование без дублирования данных, ZIP-архив папки.
- **Докачка больших файлов**: загрузка частями по 8 МБ, после обрыва связи — продолжение с места остановки (и в браузере, и в клиенте синхронизации).
- **Миниатюры на сервере**: фото (с учётом поворота из EXIF), кадр видео (ffmpeg), первая страница PDF (poppler). Кэшируются, пересоздаются при новой версии.
- Просмотр фото, видео, аудио, PDF, текста и Markdown; встроенный редактор текстовых файлов.
- Версии файлов, корзина с восстановлением на прежнее место.
- **Полнотекстовый поиск** по содержимому TXT/MD/код, PDF, DOCX, XLSX, PPTX, ODT/ODS/ODP — с русской морфологией и подсветкой найденного фрагмента.
- **Избранное, теги** (личные, цветные) и **комментарии** к файлам.

**Совместная работа**
- **Общий доступ пользователям и группам** с правами «просмотр» или «изменение»; раздел «Доступно мне»; общие папки видны и в WebDAV.
- Публичные ссылки: пароль, срок действия, загрузка гостями, QR-код, счётчик скачиваний.
- **Онлайн-редактор документов** Collabora Online / OnlyOffice через WOPI (с блокировками: пока документ открыт, другие клиенты его не перезапишут).
- **Уведомления**: с вами поделились, новый комментарий, гость загрузил файл, ссылка скоро истечёт, квота почти заполнена.
- **Журнал действий**: кто, что и когда загрузил, переименовал, удалил, скачал по ссылке.
- **Чат**: личные переписки и групповые комнаты, сообщения в реальном времени, счётчики непрочитанного, уведомления браузера.
- **Видеозвонки** в браузере (WebRTC) до 6 участников: камера, микрофон, показ экрана, входящий вызов в любом разделе.
- **Почта**: веб-клиент для ваших ящиков (Яндекс, Mail.ru, Gmail, свой сервер) по IMAP/SMTP — папки, поиск, ответ и пересылка, вложения в CloudBox и из него.

**Фото, заметки, календарь, контакты**
- **Галерея** — лента всех фото и видео по дате съёмки (EXIF), с группировкой по месяцам.
- **Заметки** в Markdown с автосохранением (обычные `.md`-файлы в папке «Заметки» — синхронизируются вместе со всем остальным).
- **Календарь (CalDAV)** и **контакты (CardDAV)** — синхронизация с телефоном через DAVx⁵, iOS/macOS, Thunderbird; повторяющиеся события.

**Клиенты**
- **WebDAV** (`/dav/`) — сетевой диск в Windows/macOS/Linux/Android, rclone; отдаёт квоту (`quota-available-bytes`), ETag папок меняется при изменениях внутри.
- **cloudbox-sync** — консольный клиент двусторонней синхронизации папки для Windows, Linux, macOS (см. ниже).
- **cloudbox-desktop** — графический клиент синхронизации: значок в трее, окно настроек, автозапуск.
- **PWA** — устанавливается на телефон как приложение; в Android появляется в меню «Поделиться».
- **Мобильное приложение** (Flutter, Android и iOS) — файлы, загрузка с телефона, автозагрузка фото и видео; см. [mobile/README.md](mobile/README.md). APK собирается в GitHub Actions.

**Безопасность**
- **Двухфакторная аутентификация (TOTP)** + 10 одноразовых кодов восстановления.
- **Вход через OIDC** (Authentik, Keycloak, Authelia, Zitadel) с PKCE и проверкой подписи токена.
- Список сеансов с завершением чужих, **журнал входов**, пароли приложений для WebDAV/CalDAV/синхронизации.
- **Шифрование файлов на сервере** AES-256-GCM (сегментами по 64 КБ — работает перемотка видео и Range-запросы).
- **Сквозное шифрование (E2E-папки)**: содержимое и имена шифруются в браузере, сервер хранит только шифротекст.
- PBKDF2-SHA256 для паролей, защита от CSRF, ограничение попыток входа, `CSP: sandbox` при отдаче файлов, строгая изоляция пользователей.

**Эксплуатация**
- **Бэкап и восстановление** одной командой (БД + файлы в один `.tar.gz`), ежедневный бэкап по расписанию с ротацией.
- **Перенос хранилища** `local ↔ s3` одной командой.
- **Метрики Prometheus** (`/metrics`), структурированные логи (`CB_LOG_FORMAT=json`).

## Быстрый старт

```bash
cp .env.example .env
# в .env обязательно задайте CB_SECRET (openssl rand -hex 32) и DB_PASSWORD
docker compose up -d
```

Откройте `http://IP-сервера:8080` и зарегистрируйте первого пользователя — он станет администратором.

### С HTTPS (нужен для WebDAV в Windows и для установки PWA)

```bash
# .env: DOMAIN=cloud.example.ru и CB_PUBLIC_URL=https://cloud.example.ru
docker compose --profile https up -d
```

Caddy сам получит сертификат Let's Encrypt. Для nginx — `deploy/nginx.conf.example`.

### Онлайн-офис (Collabora)

1. Направьте второй домен (например `office.example.ru`) на сервер.
2. В `.env`: `OFFICE_DOMAIN=office.example.ru`, `CB_WOPI_URL=https://office.example.ru`, `COLLABORA_ADMIN_PASSWORD=...`.
3. `docker compose --profile https --profile office up -d`

DOCX/XLSX/PPTX/ODT открываются щелчком прямо в браузере. Подойдёт и OnlyOffice Docs с включённым WOPI — укажите его адрес в `CB_WOPI_URL`.

### Чат и видеозвонки

Чат работает сразу, без настройки. Сообщения доставляются по Server-Sent Events, поэтому подходит любой обратный прокси. Caddy из комплекта настраивать не нужно, а nginx получает заголовок `X-Accel-Buffering: no`.

Для звонков нужно учесть три вещи:

- **HTTPS.** Браузеры дают доступ к камере и микрофону только по HTTPS (или на `localhost`).
- **TURN-сервер**, если участники в разных сетях. Без него звонок соединится только внутри одной локальной сети. Через мобильный интернет, корпоративный NAT и между разными домами нужен TURN, который ретранслирует медиапоток. В комплекте есть coturn:
  1. Сгенерируйте секрет (`openssl rand -hex 32`) и впишите в `.env`:
     ```
     CB_TURN_SECRET=<секрет>
     CB_TURN_URLS=turn:cloud.example.ru:3478?transport=udp,turn:cloud.example.ru:3478?transport=tcp
     CB_STUN_URLS=stun:cloud.example.ru:3478
     ```
  2. Запустите: `docker compose --profile https --profile talk up -d`.
  3. Откройте на сервере порты `3478/udp`, `3478/tcp` и `49160–49200/udp`. Если сервер сам за NAT (дома за роутером), пробросьте эти порты и раскомментируйте в `docker-compose.yml` строку `--external-ip`, указав в ней внешний IP.

  Браузер получает от CloudBox временные учётные данные TURN (действуют 12 часов), сам секрет на клиент не попадает. coturn не ретранслирует трафик в частные сети, так что через него нельзя добраться до внутренних адресов.
- **Размер звонка.** Звонок устроен «каждый с каждым», без медиасервера, поэтому участников не больше 6.

Чат хранит состояние звонков в памяти процесса, поэтому CloudBox должен работать в одном экземпляре. Для домашнего и небольшого офисного сервера это обычный режим.

### Почта

Раздел «Почта» подключает существующие ящики, сам CloudBox почтовым сервером не является. Нужен только постоянный `CB_SECRET`: им шифруются пароли ящиков в базе. Без него почта отключена, потому что после перезапуска сохранённые пароли нельзя было бы расшифровать.

- **Пароль приложения.** Яндекс, Mail.ru, Gmail и iCloud по IMAP не принимают основной пароль, им нужен пароль приложения. Подсказка, где его взять, появляется после ввода адреса.
- **Защита от SSRF.** Адрес сервера вводит пользователь, поэтому CloudBox подключается только к публичным адресам на стандартных почтовых портах (143, 993, 25, 465, 587, 2525) и только с шифрованием. Свой почтовый сервер в локальной сети разрешается через `CB_MAIL_ALLOW_PRIVATE=true`: только для частных адресов становится допустимым и подключение без шифрования. Нестандартные порты, например у Proton Mail Bridge (1143, 1025), добавляются через `CB_MAIL_EXTRA_PORTS`. Служебные адреса (link-local, в том числе метаданные облака 169.254.169.254, и multicast) закрыты всегда, даже при `CB_MAIL_ALLOW_PRIVATE`.
- **Безопасный показ писем.** HTML письма очищается и открывается в изолированном iframe без скриптов. Картинки из интернета по умолчанию не загружаются, чтобы отправитель не узнал по пикселю слежения, что письмо прочитано. Показать их можно одной кнопкой.
- **Ограничения против злоупотреблений.** Подключить ящик можно не чаще 10 попыток за 10 минут с одного адреса, отправить — не больше 100 писем в час от пользователя.

### S3 / Garage

1. Сгенерируйте секрет (`openssl rand -hex 32`) и впишите в `deploy/garage.toml` вместо `rpc_secret`.
2. Поднимите и настройте Garage:

```bash
docker compose --profile s3 up -d garage
docker compose exec garage /garage status                 # скопируйте ID ноды
docker compose exec garage /garage layout assign -z dc1 -c 100G <ID>
docker compose exec garage /garage layout apply --version 1
docker compose exec garage /garage bucket create cloudbox
docker compose exec garage /garage key create cloudbox-key   # покажет Key ID и Secret
docker compose exec garage /garage bucket allow --read --write --owner cloudbox --key cloudbox-key
```

3. В `.env`: `CB_STORAGE=s3`, `CB_S3_ACCESS_KEY`, `CB_S3_SECRET_KEY`; затем `docker compose --profile s3 up -d`.

Для Yandex Object Storage: `CB_S3_ENDPOINT=https://storage.yandexcloud.net`, `CB_S3_REGION=ru-central1`.

### Вход через OIDC

У провайдера создайте клиента с Redirect URI `https://cloud.example.ru/api/auth/oidc/callback`, затем в `.env`:

```
CB_OIDC_ISSUER=https://auth.example.ru/application/o/cloudbox/
CB_OIDC_CLIENT_ID=...
CB_OIDC_CLIENT_SECRET=...
CB_PASSWORD_LOGIN=false   # если нужен вход только через SSO (администраторы всё равно могут войти паролем)
```

При `CB_PASSWORD_LOGIN=false` основной пароль не принимается и в WebDAV/CalDAV/CardDAV — там работают только пароли приложений (кроме администраторов).

> **Осторожно с `CB_OIDC_LINK_BY_USERNAME=true`.** Существующий локальный пользователь привязывается к OIDC по совпадению `preferred_username`. Если провайдер позволяет пользователям самим выбирать это имя, любой может назваться `admin` и войти в чужую учётную запись, в том числе администратора. Включайте только на время миграции и только если имена у провайдера задаёт администратор.

### Сквозное шифрование (E2E-папки)

Шифрование на сервере (`CB_ENCRYPTION_KEY`, следующий раздел) защищает от кражи дисков, но ключ у сервера есть. E2E-папки защищают и от самого сервера: файлы шифруются в браузере, и ни администратор, ни тот, кто получил доступ к серверу, их не прочитает.

Создаётся папка так: **Создать → Зашифрованную папку (E2E)**. При первом создании браузер попросит придумать кодовую фразу и покажет ключ восстановления.

**Что зашифровано:**
- **Содержимое файлов.** У каждого файла свой ключ, шифрование AES-256-GCM сегментами по 64 КБ. Подмена, обрезка и перестановка сегментов обнаруживаются при расшифровке.
- **Имена файлов и вложенных папок.** На сервере лежат случайные имена, настоящие хранятся в зашифрованных метаданных папки.
- **Ключ хранилища.** Он создаётся в браузере, а на сервере лежит только обёрнутым двумя ключами: из кодовой фразы (PBKDF2-SHA256, 600 000 итераций) и ключом восстановления. Ни фразу, ни ключ сервер не получает.

**Что видно серверу:**
- имя самой E2E-папки;
- число файлов, их размеры и время изменения.

Сервер может удалить данные или вернуть старую версию метаданных. Прочитать или незаметно подменить содержимое он не может.

**Что отключено для E2E-папок:** миниатюры, поиск по содержимому, онлайн-офис, публичные ссылки и общий доступ (обмен ключами между пользователями пока не поддерживается), ZIP-архив, а также показ в WebDAV и в клиентах синхронизации: они пропускают такие папки. Переносить файлы между E2E-папкой и обычной нельзя. Саму E2E-папку целиком переносить можно.

**Защита от случайной утечки.** В E2E-папку сервер принимает только шифротекст CloudBox: заголовок `CBE1` и случайное имя. Если обычный файл по ошибке загрузить «в зашифрованную папку» через API или стороннюю программу, сервер его отклонит, и он не окажется там открытым.

> **Без кодовой фразы и ключа восстановления файлы не восстановит никто**, включая администратора. Ключ восстановления показывается один раз, храните его отдельно от компьютера.

### Шифрование файлов

```
CB_ENCRYPTION_KEY=<openssl rand -hex 32>
```

Новые файлы пишутся зашифрованными, старые читаются как есть. **Потеря ключа — потеря всех файлов**: храните ключ отдельно от бэкапов. Зашифровать уже имеющиеся файлы можно так: `backup` → новая пустая база → `restore` с заданным ключом.

## Подключение устройств

| Что | Как |
|---|---|
| Сетевой диск (WebDAV) | `https://cloud.example.ru/dav/` — Windows: «Подключить сетевой диск»; Linux: `davs://…`; macOS: ⌘K; Android: Solid Explorer, FolderSync |
| Календарь и контакты | Android: DAVx⁵ → «Вход с URL» → `https://cloud.example.ru`; iOS/macOS: учётная запись CalDAV/CardDAV; Thunderbird: календарь «В сети» |
| Автозагрузка фото | FolderSync / PhotoSync → WebDAV → папка `DCIM/Camera` → «Фото/Камера», режим «Только загрузка» |
| Отправка файлов с телефона | Установите CloudBox как приложение (меню браузера → «Установить») → в Android «Поделиться → CloudBox» |
| Папка на компьютере | `cloudbox-sync` (ниже) |

Логин — имя пользователя, пароль — **пароль приложения** из «Настроек» (при включённой 2FA основной пароль в WebDAV/CalDAV не работает).

Чужие общие папки в WebDAV видны в каталоге «Доступно мне».

## Клиент синхронизации cloudbox-sync

Готовые сборки для Windows, Linux и macOS появляются в Releases при публикации тега `v*`. Или соберите сами: `go build ./cmd/cloudbox-sync`.

```bash
export CLOUDBOX_PASSWORD=<пароль приложения>
cloudbox-sync -server https://cloud.example.ru -user andrey -local ~/CloudBox -remote /Документы -watch 30s
```

- Изменения с одной стороны копируются на другую; большие файлы загружаются частями с докачкой.
- Конфликт (правка с обеих сторон): серверная версия скачивается, локальная сохраняется как «имя (конфликт ПК дата)» и загружается следующим проходом — ничего не теряется.
- Удалённое на сервере уходит локально в `.cloudbox-trash`, удалённое локально — в корзину сервера.
- `-dry-run` показывает, что будет сделано, ничего не меняя.

### Графический клиент cloudbox-desktop

То же самое без командной строки: значок в трее и окно настроек в браузере, как у Syncthing. Скачайте `cloudbox-desktop` из Releases и запустите. Откроется окно, где нужно указать адрес сервера, имя пользователя, пароль приложения и две папки, на компьютере и на сервере.

- **Значок в трее** показывает состояние цветом: синий — всё синхронизировано, оранжевый — нужна настройка, серый — пауза, красный — ошибка. В меню значка: открыть окно, сайт CloudBox или папку, синхронизировать сейчас, пауза, выход.
- **Окно** показывает статус, статистику последнего прохода и журнал. В нём же меняются настройки и включается автозапуск при входе в систему: реестр на Windows, `~/.config/autostart` на Linux, LaunchAgent на macOS.
- **Хранение пароля.** Пароль приложения на Windows шифруется DPAPI, его может расшифровать только ваша учётная запись. В Linux и macOS он хранится в файле настроек с правами 0600. В любом случае это пароль приложения, его можно отозвать на сайте, не меняя основной.
- **Защита окна.** Окно — это локальная страница на `127.0.0.1`, доступная только по случайному токену. Другие сайты и пользователи компьютера до неё не достучатся: проверяются `Host` (защита от DNS rebinding) и `Origin` (защита от CSRF).
- **Один экземпляр.** Повторный запуск не создаёт второй клиент, а открывает окно уже работающего.
- **Ограничения платформ.** Сборка для macOS из Releases (без cgo) работает без значка в строке меню: окно открывается при запуске и при повторном запуске. Значок появится в сборке с cgo на Mac: `go build ./cmd/cloudbox-desktop`. На Linux без DBus (не в графической сессии) клиент тоже работает без значка.

## Команды

```bash
docker compose exec app cloudbox useradd -admin -quota-mb 0 admin 'StrongPass123'
docker compose exec app cloudbox passwd admin 'NewPass456'
docker compose exec app cloudbox backup -o /backups/manual.tar.gz      # бэкап БД и файлов
docker compose exec app cloudbox migrate-storage -to s3                # перенос файлов в S3
docker compose exec app cloudbox reindex                               # переиндексировать поиск
# восстановление — в новую ПУСТУЮ базу:
docker compose run --rm app restore -i /backups/cloudbox-2026-11-03.tar.gz
```

Ежедневный бэкап включается переменной `CB_BACKUP_DIR` (в compose — папка `./backups`): архив создаётся в `CB_BACKUP_HOUR`, хранятся последние `CB_BACKUP_KEEP`. Скопировать его вне сервера можно, например, `rclone sync ./backups remote:cloudbox-backups`.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `CB_LISTEN` | `:8080` | адрес сервера |
| `CB_DATABASE_URL` | — | строка подключения PostgreSQL |
| `CB_PUBLIC_URL` | `http://localhost:8080` | внешний адрес |
| `CB_SECRET` | случайный | ключ подписи cookie и токенов |
| `CB_TZ` | `Asia/Yekaterinburg` | часовой пояс для EXIF и календаря |

## Устройство

```
cmd/cloudbox         сервер, фоновые задачи, CLI (backup/restore/migrate-storage/reindex)
cmd/cloudbox-sync    консольный клиент двусторонней синхронизации
cmd/cloudbox-desktop графический клиент синхронизации: трей + локальный веб-интерфейс
internal/syncclient  движок синхронизации (общий для обоих клиентов)
internal/files       ядро: дерево, версии, корзина, квоты, права, шаринг, докачка, миниатюры,
                     поиск, теги, комментарии, журнал, уведомления, блокировки WOPI
internal/auth        пользователи, сессии, 2FA, пароли приложений, журнал входов, OIDC-пользователи
internal/oidc        OpenID Connect: discovery, PKCE, проверка подписи по JWKS (без зависимостей)
internal/dav         WebDAV поверх ядра + виртуальная папка «Доступно мне»
internal/pim         CalDAV/CardDAV (go-webdav) с хранением в PostgreSQL
internal/wopi        WOPI-хост для Collabora/OnlyOffice
internal/talk        чат, доставка событий (SSE), сигнализация WebRTC, временные учётные данные TURN
internal/mail        почтовый клиент: IMAP/SMTP с проверкой адресов (SSRF), разбор MIME, шифрование паролей ящиков
internal/mail/mailtest  IMAP/SMTP-сервер в памяти для тестов
internal/netx        адрес клиента за доверенным прокси, ограничение частоты попыток
internal/media       EXIF, миниатюры (изображения, ffmpeg, pdftoppm)
internal/textext     извлечение текста для поиска (PDF, DOCX, XLSX, PPTX, ODF, текст)
internal/storage     local, S3 (свой клиент SigV4), шифрующая обёртка AES-256-GCM
internal/backup      бэкап/восстановление, перенос между хранилищами, расписание
internal/metrics     Prometheus
web/static           веб-интерфейс на чистом JS (go:embed), PWA, service worker
mobile               мобильное приложение на Flutter (Android, iOS)
```

- **Метаданные в PostgreSQL, байты в хранилище.** Версии ссылаются на блоб по ключу; несколько версий могут ссылаться на один блоб (копирование, восстановление версии). Блоб удаляется фоновой задачей только когда ссылок не осталось.
- **ETag папок** поддерживается триггером: любое изменение внутри меняет ETag всех родителей и корня пользователя — клиент синхронизации за один запрос узнаёт, что ничего не поменялось.
- **Права**: доступ к узлу определяется ближайшим расшаренным предком; все операции выполняются от имени владельца дерева, квота тоже его.
- **Поиск**: фоновая очередь извлекает текст, PostgreSQL хранит `tsvector` (русская морфология + точные слова), GIN-индекс.

## Сборка без Docker

```bash
go build -o cloudbox ./cmd/cloudbox
CB_DATABASE_URL=postgres://... CB_SECRET=... ./cloudbox
```

Для миниатюр видео и PDF, поиска по PDF и бэкапов нужны `ffmpeg`, `poppler-utils`, `postgresql-client` (в Docker-образе уже есть).

В `go.mod` модули `golang.org/x/*` заменены на официальные зеркала на GitHub (`github.com/golang/*`) — для сборки там, где закрыт `proxy.golang.org`. Если сеть открыта, `replace` можно удалить.

## Чего пока нет

- В мобильном приложении: фоновой автозагрузки при закрытом приложении, чата, почты и E2E-папок (они доступны в веб-версии и PWA); сборка под iOS не проверялась (нужен Mac).
- Синхронизации по запросу (файлы-заглушки, которые скачиваются при открытии, как OneDrive Files On-Demand): клиент хранит локальную копию всей папки.
- Собственного почтового сервера: почта — клиент к существующим ящикам (свой сервер можно поднять, например, на docker-mailserver).
- Общего доступа к E2E-папкам (нужен обмен открытыми ключами между пользователями) и работы с ними в клиентах синхронизации и WebDAV — сейчас E2E-папки открываются только в веб-интерфейсе.
- Больших видеоконференций: звонок «каждый с каждым», до 6 участников, без медиасервера (SFU).
